# Implementation Plan - Phase 2: Attendance & Leave Management

## Overview
This plan outlines the steps to implement Phase 2: Attendance & Leave Management based on the provided implementation plan.

## Database Layer
1. Create schema_attendance_leave.sql with the following tables:
   - attendances (clock_in, clock_out, location, photo, status)
   - shifts and employee_shifts
   - leave_types, leave_balances, leave_requests
   - notification_templates and notifications
2. Apply the schema to the PostgreSQL database.

## Backend Layer (Go)
1. Modify models/core_hr_models.go:
   - Add structs for Attendance, Shift, LeaveRequest, and Notification
2. Create repository/attendance_repository.go:
   - Implement ClockIn, ClockOut, and history fetching
   - Implement shift assignment logic
3. Create repository/leave_repository.go:
   - Implement real-time balance calculation engine
   - Implement leave request submission and approval workflow
4. Create attendance_handlers.go:
   - Implement REST endpoints for attendance
5. Create leave_handlers.go:
   - Implement REST endpoints for leave management
6. Create notification_engine.go:
   - Implement reusable service for in-app and email/WhatsApp alerts

## Frontend Layer (React/TypeScript)
1. Create services/attendance.service.ts and services/leave.service.ts:
   - Implement API integration functions
2. Create pages/attendance/AttendanceOverview.tsx:
   - Implement premium "Daily Card" with Clock-in/out button
   - Add real-time timer and activity log
   - Add geolocation tracking indicator
3. Create pages/leave/LeaveManagement.tsx:
   - Implement grid showing different leave balances
   - Create modal-based leave request form (using premium dialog style)
   - Add calendar view for pending/approved leaves
4. Create pages/attendance/ShiftManagement.tsx:
   - Implement admin tool to define shifts and assign to employees
5. Update config/routes.ts:
   - Enable new routes for Attendance and Leave

## Verification Plan
### Automated Tests
1. API Integration:
   - Test valid clock-in/out
   - Test invalid clock-in (e.g., clocking in twice)
2. Leave Logic:
   - Verify that requesting 3 days of leave correctly reduces the calculated balance

### Manual Verification
1. Open Attendance Dashboard
2. Perform Clock-In:
   - Verify location data capture (if allowed by browser)
3. Submit Leave Request:
   - Check if it appears in the "Pending" list
4. (Admin) Approve Leave:
   - Verify that the balance updates immediately

## Dependencies
- PostgreSQL database
- Go backend
- React/TypeScript frontend

## Estimated Effort
- Database: 2 hours
- Backend: 8 hours
- Frontend: 10 hours
- Verification: 4 hours
